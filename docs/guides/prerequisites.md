# 接入准备

开始 SDK 集成前，请确认以下前置条件已就绪。任一项缺失，请先联系平台管理员。

## AccessKey ID / Secret

SDK 的身份凭证对，用于向 Edge 服务进行签名认证。在控制台创建 Deployment 时生成。

- **使用**：SDK 初始化时作为身份凭证传入，运行期不变。各平台具体字段名见各 Demo 仓库的「参数说明」（见 [平台与框架适配](platforms.md)）
- **注意事项**：建议应用开启混淆，避免 AccessKey 泄漏

## Edge 初始化节点地址列表

SDK 的初始 Edge 接入点——DoH 解析和加密隧道的第一跳。

- **对应 SDK 参数**：`edgeAddresses`
- **数量要求**：至少 1 个；推荐多个（域名 + IP 混用），以便在 DNS 解析失败或部分节点不可达时仍能建立连接
- **来源**：
    - **自部署边缘**：客户自行部署的 Edge 节点地址（EIP）
    - **订阅边缘**：订阅其他租户后获得的 CNAME 域名或 EIP 地址
- **注意事项**：
    - 初始化地址中的域名必须能通过外部公共 DNS 解析。推荐使用平台的 DNS 路由功能，同时配置拨测过滤不可用节点
    - 配置了域名时，SDK 启动后会优先通过 Edge DoH 解析域名获取 Edge 地址

完整字段定义见 [参考 / 初始化参数 / Edge 节点地址列表](../reference/init-parameters.md#edge-节点地址列表必填)。

## 控制台添加资源配置（可选）

每个需要通过 SecureProxy 访问的**业务域名**（业务流量的目标域名）都需要在控制台**定义为一个资源**，关联到对应的源站及基础属性。

- **为什么关键**：未包含在控制台资源中的域名，不会通过 SecureProxy 访问
- **配置内容**：资源域名、源站地址、基础访问策略等
- **详见**：**控制台配置指南**（请参考产品控制台文档）

## 控制台添加 DoH 路由规则（可选）

为域名配置 **Edge DoH 规则**——这是 **DoH Routing 的核心**：Edge 基于客户端上下文（设备信息、网络环境、风险等级等）为每次请求返回最合适的节点地址。

推荐为需要保护的资源域名，和初始化地址中的域名，配置 DoH 路由规则。未添加则命中默认规则，走第三方公共 DNS（Google Cloud DNS、Alibaba Cloud DNS、Tencent Cloud DNS）解析后响应。

- **启用步骤**：完整启用步骤（控制台 + SDK 两侧）见 [启用 EdgeDoH](enable-edgedoh.md)
- **详见**：**控制台配置指南**（请参考产品控制台文档）

## 获取 SDK 包

在控制台 **端点 → 设备** 界面，根据应用类型获取对应平台的 SDK 包。

- **来源**：SDK 官方发布渠道
- **版本选择**：使用当前稳定版本；各平台最低 SDK / 系统版本要求见 [平台与框架适配](platforms.md)
